### 1. Основные концепции

Хеш-таблица — это структура данных, которая хранит пары «ключ — значение» (или просто элементы в множестве) и использует хеш-функцию для вычисления индекса в массиве, где элемент будет храниться.

Ключевые элементы:

- **Хеш-функция** — преобразует ключ в целое число (хеш). В Python за это отвечает встроенная функция `hash()`.
    
- **Массив (бакеты)** — непрерывная область памяти, разделённая на ячейки (слоты). Каждый слот может хранить данные (или быть пустым).
    
- **Разрешение коллизий** — метод обработки ситуаций, когда разные ключи дают одинаковый хеш (или индекс).

### 2. Требования к ключам

Ключи в словаре и элементы множества должны быть **хешируемыми** (hashable). Это значит:

- У объекта должен быть метод `__hash__()`, который возвращает целое число, неизменное в течение жизни объекта.
    
- Объект должен поддерживать сравнение на равенство (`__eq__()`), чтобы можно было отличить разные ключи с одинаковым хешем.
    
- Обычно хешируемы неизменяемые типы: `int`, `float`, `str`, `tuple` (если все элементы хешируемы), `frozenset`. Пользовательские классы по умолчанию хешируемы (используют `id()`), но при переопределении `__eq__` нужно переопределить и `__hash__`.

### 3. Структура хеш-таблицы в CPython

В CPython словарь (`dict`) исторически претерпел изменения. До версии 3.6 использовалась «классическая» таблица с отдельным массивом записей. Начиная с Python 3.6 (и как гарантия с 3.7) используется **компактное представление** (compact dict), которое уменьшает потребление памяти и сохраняет порядок вставки.

#### Компактный dict (Python 3.7+)

Словарь состоит из двух основных массивов:

1. **Массив индексов** (`indices`) — массив целых чисел (размером в степень двойки, обычно). Каждый элемент указывает позицию в массиве записей или специальное значение (например, -1), если слот пуст.
    
2. **Массив записей** (`entries`) — динамический массив, хранящий фактические данные в порядке вставки. Каждая запись содержит:
    
    - хеш ключа,
        
    - указатель на ключ,
        
    - указатель на значение.
        

**Как это работает:**

- Для данного ключа вычисляется хеш.
    
- Берётся младшие биты хеша (зависящие от текущего размера `indices`) для получения индекса в массиве `indices`.
    
- По этому индексу смотрим значение в `indices`. Если оно равно -1, слот пуст.
    
- Иначе это индекс в `entries`, по которому лежит реальная запись.
    
- Проверяем, совпадает ли ключ (сначала сравниваем хеши, потом через `__eq__`). Если нет — разрешаем коллизию (линейное пробирование).
    

Преимущества такого подхода:

- **Экономия памяти** — массив `indices` занимает меньше места, чем старый массив записей (в старом подходе каждая запись хранилась в основном массиве, даже если слот пуст).
    
- **Сохранение порядка вставки** — записи добавляются в конец `entries`, поэтому при итерации они идут в порядке добавления.
    
- **Более быстрая итерация** — проходим по плотному массиву `entries`, пропуская пустые слоты.

## Пошаговая вставка с картинками

### Шаг 0: Пустой словарь

Indices все -1, entries пуст.

```python
indices (size=8):
[ -1, -1, -1, -1, -1, -1, -1, -1 ]
entries:
[]
```

### Шаг 1: Добавляем `"a": 1`

- Хеш `"a"` = 12345 (условно).
    
- Индекс в indices = 12345 % 8 = 3.
    
- Занимаем indices[3] = 0 (порядковый номер новой записи).
    
- Добавляем запись в entries: `(12345, "a", 1)`.
    

```python
indices:
[ -1, -1, -1, 0, -1, -1, -1, -1 ]
entries:
[0] (12345, "a", 1)
```

### Шаг 2: Добавляем `"b": 2`

- Хеш `"b"` = 67890.
    
- Индекс = 67890 % 8 = 5.
    
- indices[5] = 1.
    
- entries добавляем `(67890, "b", 2)`.

```python
indices:
[ -1, -1, -1, 0, -1, 1, -1, -1 ]
entries:
[0] (12345, "a", 1)
[1] (67890, "b", 2)
```

### Шаг 3: Добавляем `"c": 3`

- Хеш `"c"` = 13579.
    
- Индекс = 13579 % 8 = 7.
    
- indices[7] = 2.
    
- entries: `(13579, "c", 3)`.
    

```python
indices:
[ -1, -1, -1, 0, -1, 1, -1, 2 ]
entries:
[0] (12345, "a", 1)
[1] (67890, "b", 2)
[2] (13579, "c", 3)
```

## Коллизия — когда двум ключам нужен один индекс

Пусть хеш ключа `"x"` даёт индекс 3 (как у `"a"`). Но indices[3] уже занят (там 0). Это коллизия.

Python не кладёт новое значение поверх старого. Он начинает **пробирование** — ищет другой свободный индекс в indices, используя специальную формулу.

Допустим, пробирование привело к индексу 4 (indices[4] == -1). Тогда:

- indices[4] = 3 (следующий номер записи).
- entries добавляется `(хеш_x, "x", 4)`.

```python
indices:
[ -1, -1, -1, 0, 3, 1, -1, 2 ]
entries:
[0] (12345, "a", 1)
[1] (67890, "b", 2)
[2] (13579, "c", 3)
[3] (98765, "x", 4)   <-- новая запись
```

🔍 При поиске `"x"`:

- Хеш → индекс 3 → indices[3] = 0 → entries[0] — это `"a"`, не подходит.
    
- Пробирование → следующий кандидат 4 → indices[4] = 3 → entries[3] — `"x"`, совпало.
