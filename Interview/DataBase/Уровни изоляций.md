### 1. Что такое уровень изоляции?

Уровень изоляции определяет степень защиты одной транзакции от побочных эффектов, производимых параллельно выполняющимися другими транзакциями.
### 2. Проблемы параллельного доступа (аномалии)
#### Dirty Read (Грязное чтение)

Чтение незакоммиченных данных другой транзакции.

```sql
-- Транзакция 1
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
-- НЕ КОММИЧУ!
-- Транзакция 2 (в этот момент)
BEGIN;
SELECT balance FROM accounts WHERE id = 1;
-- При уровне READ UNCOMMITTED увидит -100
-- При READ COMMITTED увидит старый баланс
-- Транзакция 1
ROLLBACK; -- Отмена, баланс вернулся к исходному
```
#### Non-repeatable Read (Неповторяющееся чтение)

Данные меняются при повторном чтении в одной транзакции.

```sql
-- Транзакция 1
BEGIN;
SELECT balance FROM accounts WHERE id = 1; -- Результат: 1000
-- Транзакция 2
BEGIN;
UPDATE accounts SET balance = 500 WHERE id = 1;
COMMIT; -- Зафиксировали изменение
-- Транзакция 1 (продолжение)
SELECT balance FROM accounts WHERE id = 1; -- Результат: 500 (изменилось!)
COMMIT;
```

#### Phantom Read (Фантомное чтение)

Появляются новые строки при повторном чтении.

```sql
-- Транзакция 1
BEGIN;
SELECT * FROM products WHERE price > 1000; -- Нашлось 5 товаров
-- Транзакция 2
BEGIN;
INSERT INTO products (name, price) VALUES ('iPhone', 1200);
COMMIT;
-- Транзакция 1 (продолжение)
SELECT * FROM products WHERE price > 1000; -- Нашлось 6 товаров (появился фантом)
COMMIT;
```

#### Lost Update (Потерянное обновление)

Одна транзакция затирает изменения другой.

```sql
-- Транзакция 1 (снятие 100)
BEGIN;
SELECT balance FROM accounts WHERE id = 1; -- Видит 1000
-- Считает новый баланс: 1000 - 100 = 900
UPDATE accounts SET balance = 900 WHERE id = 1;
COMMIT;
-- Транзакция 2 (снятие 200) началась параллельно
BEGIN;
SELECT balance FROM accounts WHERE id = 1; -- Тоже видит 1000
-- Считает новый баланс: 1000 - 200 = 800
UPDATE accounts SET balance = 800 WHERE id = 1;
COMMIT; -- Итог: 800, хотя должно быть 700
```

### 3. Read Uncommitted (Чтение незафиксированных данных)

**Характеристики:** Минимальная защита, максимальная скорость.

```sql
-- Установка уровня
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
-- Демонстрация Dirty Read
-- Сессия 1
BEGIN;
UPDATE accounts SET balance = 0 WHERE id = 1;
-- Не коммитим!
-- Сессия 2
BEGIN;
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
SELECT balance FROM accounts WHERE id = 1; 
-- Вернёт 0! Хотя транзакция 1 ещё не закоммичена
-- Сессия 1
ROLLBACK; -- Фактически баланс остался прежним
-- Сессия 2 работала с несуществующими данными
```

### 4. Read Committed (Чтение зафиксированных данных)

**Характеристики:** Только закоммиченные данные, уровень по умолчанию в PostgreSQL.

```sql
-- Установка уровня
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
-- Демонстрация защиты от Dirty Read
-- Сессия 1
BEGIN;
UPDATE accounts SET balance = 0 WHERE id = 1;
-- Сессия 2
BEGIN;
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
SELECT balance FROM accounts WHERE id = 1; 
-- Вернёт СТАРЫЙ баланс (защита от грязного чтения)
-- Сессия 1
COMMIT; -- Зафиксировали изменения
-- Сессия 2 (тот же запрос)
SELECT balance FROM accounts WHERE id = 1; 
-- Вернёт 0 (произошло неповторяющееся чтение!)
COMMIT;
```

### 5. Repeatable Read (Повторяемое чтение)

**Характеристики:** Снимок данных на начало транзакции.

```sql
-- Установка уровня
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
-- Демонстрация защиты от неповторяющегося чтения
-- Сессия 1
BEGIN;
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
SELECT * FROM accounts WHERE id = 1; -- Баланс: 1000
-- Сессия 2
UPDATE accounts SET balance = 500 WHERE id = 1;
COMMIT; -- Изменение зафиксировано
-- Сессия 1
SELECT * FROM accounts WHERE id = 1; -- Баланс: 1000 (старый снимок!)
SELECT * FROM accounts WHERE id = 1; -- Баланс: 1000 (всегда одинаково)
COMMIT;
-- После COMMIT новый запрос увидит изменения
SELECT * FROM accounts WHERE id = 1; -- Баланс: 500
```

### 6. Serializable (Сериализуемый)

**Характеристики:** Полная изоляция, максимальная защита.

```sql
-- Установка уровня
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
-- Демонстрация защиты от фантомов
-- Сессия 1
BEGIN;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
SELECT COUNT(*) FROM products WHERE price > 1000; -- 5 товаров
-- Сессия 2
BEGIN;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
INSERT INTO products (name, price) VALUES ('iPhone', 1200);
COMMIT; -- Успешно вставилось
-- Сессия 1
SELECT COUNT(*) FROM products WHERE price > 1000; -- Всё ещё 5 (защита)
UPDATE products SET price = price * 1.1 WHERE price > 1000;
COMMIT; -- ERROR:  could not serialize access due to concurrent update
-- Транзакция откатится, нужно повторить
```
