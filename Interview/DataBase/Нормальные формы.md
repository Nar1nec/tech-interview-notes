**Нормальные формы** — это правила организации таблиц в базе данных, которые помогают избежать дублирования данных и проблем при их обновлении.\

### ① Первая нормальная форма (1НФ)

**Определение:** В таблице нет повторяющихся групп данных, и каждое поле содержит только одно значение.

#### ❌ Нарушение 1НФ:

```sql
-- В одной ячейке несколько значений
CREATE TABLE student_bad (
    id INT PRIMARY KEY,
    name TEXT,
    phones TEXT  -- "89001234567, 89119876543, 89223334455"
);
-- Или несколько колонок для одного типа данных
CREATE TABLE product_bad (
    id INT PRIMARY KEY,
    name TEXT,
    phone1 TEXT,  -- ужас!
    phone2 TEXT,
    phone3 TEXT
);
```

#### ✅ Соответствие 1НФ:

```sql
-- Каждое значение в отдельной строке
CREATE TABLE student (
    id INT PRIMARY KEY,
    name TEXT
);
CREATE TABLE student_phone (
    student_id INT REFERENCES student(id),
    phone TEXT PRIMARY KEY,
    phone_type TEXT  -- "мобильный", "домашний"
);
```

#### 📋 Правила 1НФ:

- ✅ В каждой ячейке — одно значение
- ✅ Нет массивов, списков, json с кучей данных
- ✅ Все строки уникальны (есть первичный ключ)
- ✅ Порядок строк не важен

### ② Вторая нормальная форма (2НФ)

**Определение:** Таблица находится в 1НФ, и все неключевые поля зависят от ВСЕГО первичного ключа (а не от его части).

> Применяется только для таблиц с составным первичным ключом.

#### ❌ Нарушение 2НФ:

```sql
-- Составной ключ: (order_id, product_id)
CREATE TABLE order_items_bad (
    order_id INT,
    product_id INT,
    quantity INT,
    product_name TEXT,      -- ❌ зависит только от product_id
    product_price DECIMAL,  -- ❌ зависит только от product_id
    order_date DATE,        -- ❌ зависит только от order_id
    customer_name TEXT,     -- ❌ зависит только от order_id
    PRIMARY KEY (order_id, product_id)
);

-- Данные:
-- Заказ 1: купили телефон и чехол
-- Название телефона повторяется 2 раза?!
```

#### ✅ Соответствие 2НФ:

```sql
-- Заказы
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    order_date DATE,
    customer_name TEXT
);
-- Товары
CREATE TABLE products (
    product_id INT PRIMARY KEY,
    product_name TEXT,
    product_price DECIMAL
);
-- Связь заказов и товаров (только то, что зависит от всего ключа)
CREATE TABLE order_items (
    order_id INT REFERENCES orders(order_id),
    product_id INT REFERENCES products(product_id),
    quantity INT,
    PRIMARY KEY (order_id, product_id)
);
```

#### 📋 Правила 2НФ:

- ✅ Сначала 1НФ
- ✅ Таблица в 2НФ или нет составного ключа
- ✅ Каждое неключевое поле зависит от всего ключа целиком

### ③ Третья нормальная форма (3НФ)

**Определение:** Таблица находится в 2НФ, и все неключевые поля зависят ТОЛЬКО от первичного ключа (не зависят друг от друга).

#### ❌ Нарушение 3НФ:

```sql
CREATE TABLE orders_bad (
    order_id INT PRIMARY KEY,
    customer_id INT,
    customer_name TEXT,     -- ❌ зависит от customer_id, а не от order_id
    customer_address TEXT,  -- ❌ зависит от customer_id
    product_id INT,
    product_name TEXT,      -- ❌ зависит от product_id
    quantity INT
);
-- Проблема: если у клиента сменился адрес,
-- нужно менять во всех его заказах!
```


#### ✅ Соответствие 3НФ:

```sql
-- Клиенты
CREATE TABLE customers (
    customer_id INT PRIMARY KEY,
    customer_name TEXT,
    customer_address TEXT
);
-- Товары
CREATE TABLE products (
    product_id INT PRIMARY KEY,
    product_name TEXT
);
-- Заказы
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT REFERENCES customers(customer_id),
    order_date DATE
);
-- Детали заказа
CREATE TABLE order_items (
    order_id INT REFERENCES orders(order_id),
    product_id INT REFERENCES products(product_id),
    quantity INT,
    PRIMARY KEY (order_id, product_id)
);
```

#### 📋 Правила 3НФ:

- ✅ Сначала 2НФ
- ✅ Нет транзитивных зависимостей (A → B → C)
- ✅ Каждое поле хранит факт только о том объекте, который идентифицирует ключ
